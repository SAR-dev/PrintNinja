# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Calendar Versioning](YYYY.MMDD.patch) — see the crate version in `src-tauri/Cargo.toml`.

## [Unreleased]

### Added

- **Brand moments and a non-status accent.** A `highlight` token (violet, off every status hue, with a lifted dark-theme value) plus a matching `Badge` variant marks attention that is not a state: community templates published in the last 14 days wear a "New" badge, and a one-time "First print — nice job" pill appears on the first completed print (desktop banner and phone card, shown once via a localStorage flag). Empty-state and sign-in screens now carry the logo/icon on a brand-soft tile. All additions are tokens covered by the contrast tests, and `docs/UI_GUIDE.md` documents them.
- **Toasts on phones get a close button.** Every toast on Android shows a visible ✕ (the Toaster's `closeButton`); swipe-down at the bottom edge was the only dismissal and is cramped for a thumb. Desktop toasts are unchanged.
- **Android local network permission: explained, asked once, never random.** The first time PrintNinja needs your local network (finding network printers, printing to an IP address, or reaching a paired PC) it shows a short explanation and asks once via Android's system dialog. While the permission is off, the Add Printer sheet and the Devices page say so with an inline notice offering "Allow access" or "Open settings", and a print that would need the network fails with a message naming the permission instead of hanging — Retry works as soon as it is on. Bluetooth and USB printers never need it.
- **Refresh anything, from anywhere, on purpose.** Every entry point now runs one shared manual refresh: the topbar "Synced" badge became a refresh button (hover for the last-sync detail), Templates, Printers and History gained header refresh buttons, the command palette has a Refresh action, the Settings sync card reuses the same one, and on Android you can pull down the page to refresh. A success toasts "Up to date"; a failure names exactly what failed and offers a Retry tap; a part that can't run (local network permission off) tells you why without failing the rest. Refreshing never triggers the Android permission prompt, never touches the server when you're signed out, and can never clobber unsaved template edits — navigating away mid-refresh simply drops the page from the refresh.
- **Bluetooth pacing, tunable per printer.** Driverless Bluetooth jobs are written in small chunks with a short pause between them (default 512 bytes / 50 ms) so a slow thermal head keeps up instead of dropping the job, and the connection is flushed and given a moment to settle before it closes. If a chunk fails, the error says how many bytes made it. The chunk size (32–8192 bytes) and pause (0–2000 ms) are per-printer settings under the printer form's Advanced section (visible for direct, driverless Bluetooth only); leaving a field blank keeps the built-in default.

- **ESC/POS image band height, tunable per printer.** An ESC/POS page is sent as a run of `GS v 0` raster commands, 256 rows each. Some compact printers (a Toshiba B-FP2D in ESC/POS mode printed two stray characters instead of the test page) accept text but not tall raster bands. The band height (8–2303 rows) is now a per-printer setting under the printer form for ESC/POS rows; leave it blank for the built-in 256, or try 64 or 24. The default output is byte-for-byte unchanged. A PC rendering for a paired phone (render sharing) still uses the default band height, since it never sees the phone's printer row.
- **The label-track core now lives in the repo.** The label printing engine from the PrintNinja-Next rewrite (scene templates → native/raster encoding → delivery, `core/{scene,browser,render,planner,profiles,encoders,transport,job}`) is vendored into this repo as workspace crates, with its golden-file suite and the delivery e2e suites (real transports against a virtual printer fixture). `src-tauri` is now a member of a Rust workspace rooted at the repository root, so `Cargo.lock` and the default `target/` moved to the root and the CI, Docker and release paths follow. No user-visible change: nothing in the app calls the new crates yet, and the existing print path is untouched.
- **The label track gets its pipeline wired in.** Scene (label) templates can now be saved, prepared and printed from the backend: the `templates` table gained a `track` column — `html` is the existing document track, `scene` is the label track, whose serialized scene template lives in a new `scene_json` column, and every existing row stays `html` — plus four commands. `label_save_template` writes a scene row through the same write path as document templates; `label_prepare` validates, plans and renders a scene job and reports what it would print (units, pages, byte count) without touching the wire; `label_print` prepares and then delivers the units over the app's own transports under the printer's queue permit, recording the job in History with the honest result words (confirmed, sent to the printer, partially printed, failed); `label_list_profiles` lists the 11 bundled printer profiles. The printer-class rule is enforced at plan time: a scene that needs a native or raster path is refused for a PDF/document printer, and a PDF scene is refused for a command-language head, before any bytes move. No user-visible change yet — the label designer UI and print-flow routing land in a later milestone, and the document track is untouched.
- **A saved label printer can name the model it prints with.** The `printers` table gained a nullable `label_profile` column holding one of the 11 bundled profile ids, and a `label_set_printer_profile` command sets (or clears) the pick per saved printer. The pick is validated at write time: the id must name a bundled profile, and that profile must speak the printer's language family (a raster row takes the ESC/POS family) — a refused pick never touches the row. A row without a pick prints scene jobs with the language-based default (ZT411 for ZPL, QL-820NW-B for TSPL, CT-S500 for CPCL, the generic 58 mm thermal for ESC/POS, office laser for PDF), and a pick carries the row's own DPI and paper width into the model geometry. `label_prepare` now reports which model the job prepared against and whether it was the user's pick or the default, so the UI can show the latter as "auto". No user-visible change yet — the model picker in the printer UI lands with the label designer, and the document track is untouched.
- **The label track's scene core now lives in the frontend.** The label editor core is ported from the PrintNinja-Next reference: `src/lib/scene/schema.ts` (the TypeScript mirror of the scene template format — media, elements, `{{field}}` bindings, fonts — kept field-for-field identical to the Rust `pn-scene` crate) and `src/lib/scene/editor-model.ts` (the pure editor state: element paths, insert/update/remove, and the move/resize/clamp maths in millimetres). The typed IPC surface gained the five label commands (`label_save_template`, `label_prepare`, `label_print`, `label_list_profiles`, `label_set_printer_profile`) with their response shapes, the template rows now carry their `track` and `scene_json`, and printer rows expose the `label_profile` pick (null means the language-based default applies). No user-visible change yet — the label designer, template badges, print-flow routing and the per-printer model picker land in the following commits, and the document track is untouched.
- **The label designer is in the Designer page.** Opening a scene (label) template now swaps the document workspace for the label editor: the canvas draws the template in millimetres (text, image, barcode, QR, line, rectangle, frame and group elements), with element selection, drag (clamped so a child never leaves its frame), resize, arrow-key nudge, sibling reorder, media switching and an undo/redo stack that coalesces bursts of the same action. A new-label dialog creates a blank label template, and the toolbar's Save writes the scene into the row's `scene_json` — local-only, no server sync — with the unsaved-edits discard guard now covering both tracks. A Preview button prepares the current scene through the same `label_prepare` path the print itself takes, against the chosen printer at that printer's own DPI, and reports what would go out: the path (native, raster or PDF), the model profile used, page and byte counts, and — when the backend returns preview images — a 1-bit bitmap of each sheet. The track follows the template row's `track` column: a label template opens in the label editor, an HTML document template in the document workspace, and each track's behaviour is untouched by the other.
- **The Templates list shows both tracks, badged, and each has its own create flow.** Every row on the Templates page's Mine tab now wears a badge naming its print track — "Label" for scene rows, "Document" for everything else — in the table and on the phone card alike, and the header's New menu (PC-only, creating a template is a PC-side action) offers both "New label template" and "New document template"; each deep-links into the Designer, which opens the matching create dialog — the local-only new-label dialog for a label, the server-first pack-and-name flow for a document. On an account with no templates at all, the Designer's empty state now offers both create buttons instead of the single document one. The document track's behaviour is unchanged.
- **Raw console (developer tool).** A new "Developer tools" toggle in Settings → Diagnostics (off by default) unlocks a raw console page that sends hand-crafted byte payloads to a printer over the same path as Test Print. Paste bytes as text (with `\n`/`\r`/`\t`/`\\`/`\xHH` escapes) or as hex, or start from one of 19 pinned templates — text, barcodes, QR, shapes, CJK and raster rows in ZPL, ESC/POS, TSPL and CPCL — and see the decoded byte count before sending. Optional chunk size, chunk pause and settle time apply the driverless pacing, and the report shows bytes sent, per-phase timings and the options actually applied. CJK and raster templates carry an explicit "garbled output is expected" note. The backend logs byte counts and timings only — never the payload. Normal printing is unaffected; the page is unreachable while the toggle is off.
- **The Print page follows the template's track.** Picking a label (scene) template switches the print flow to the label track: the preview prepares the scene through the same `label_prepare` path the print itself takes and draws the returned 1-bit bitmap sheets (a PDF page shows a note instead), and Print sends the job through `label_print` — confirmed, sent but unconfirmed, partially printed and failed all surface with their honest words in the result banner, and a data-URL fetch failure fails the print, since the label command takes the records and there is no server-side fallback. The printer picker on the label track offers only the saved label printers, and picking the template while a non-label printer is selected moves the selection to a saved label printer — or to none, with the existing "choose a printer" blocker, when there is none; document (HTML) templates keep today's rule that every printer is offered. The document track's behaviour is unchanged.
- **The per-printer label model picker is in Printer Setup.** The printer form's Advanced section gained a "Label model" field (label languages only — it is absent on a PDF/document row) listing the bundled models of that row's language family, with "Auto (language default)" as the default. Saving a changed pick stores it per row via `label_set_printer_profile` in a second call after the row itself is saved — the same shape as the Bluetooth pacing and ESC/POS band height, sent only when the pick actually differs from what the row already carries (switching back to Auto sends null, restoring the language default), and a failed call loses only the pick, never the row. Changing a row's language orphans the pick, which belongs to the old family, and the field starts over at auto. The document track's behaviour is unchanged.
- **The e2e fake agent answers the label track for real.** The browser-side stand-in for the backend used to acknowledge the seven label commands without behaviour; it now implements them the way the Rust pipeline does: `label_list_profiles` returns the 11 bundled models, `label_set_printer_profile` sets or clears the per-printer pick with the same validation (bundled id, language family), scene templates save and update through `label_save_template`, `label_prepare`/`label_preview` validate the scene and records, resolve the effective profile (user pick with the row's geometry, or the language default), route to the output path (native, raster, PDF-with-fallback, or the browser path for HTML-format scenes) and report units, pages, bytes and 1-bit sheet previews, `label_print` runs the same checks and then records the job with the honest result word, and `label_encode_symbol` encodes the designer's canvas symbols. Saved template rows carry their track and scene payload, and printer rows carry the model pick, so Playwright suites can now drive the label flows against the same wire shapes, resolution order and error strings the real backend answers with. The document track's behaviour is unchanged.

### Fixed

- **Android Bluetooth prints that "succeeded" but came out blank or partial.** A driverless Bluetooth send used to hand the whole job to the RFCOMM socket in one go and close it immediately; a head that is slower than the pipe drops the overflow and the app still reports success. The write is now paced (see Added above) and the whole send stays under the existing 30 s Bluetooth timeout.
- **The Add Printer sheet closes after a one-tap add.** Adding a detected device (network or Bluetooth) with the one-tap Add left the sheet open — only Save closed it. A successful one-tap add now closes the sheet and resets the form just like Save. A failed add keeps the sheet open for a retry, and a double-tap while an add is in flight can no longer add the printer twice.
- **Windows USB printers now declare PDF when the queue supports it.** USB sends previously always went out as `RAW`, which garbled PDF-language printers on GDI-only drivers; they now use the same datatype selection as the spooler path.
- **Windows Bluetooth (direct COM) checks the printer before sending.** A Bluetooth printer that is out of paper, jammed or offline now refuses the job with a clear message instead of silently swallowing it — matching the pre-send fault detection the raw-TCP, Linux Bluetooth and Android paths already had.
- **IPP printers declare the correct document format.** Command-language jobs (ESC/POS, ZPL, TSPL, …) sent to an IPP endpoint are now declared `application/octet-stream` instead of being mislabeled as PDF.
- **Android network discovery lists raw-TCP printers.** JetDirect/9100 printers found by the mDNS browse now appear in the add-printer flow instead of being silently dropped.
- **Multi-page PDFs to label printers warn before the job starts.** A PDF sent to a command-language head (ESC/POS, TSPL, ZPL, CPCL) prints only its first page. The page count is now probed before the job is created, so "The PDF has N pages; only the first page will be printed" rides the response up front — including on retries. Pdf-language printers (IPP / system spooler) take the whole document and are unaffected.
- **Android PDFs print at their own page size instead of A4.** Android ships without a bundled PDF reader, so PDF jobs fell back to A4 geometry. The Android plugin now reports the document's first-page size and total page count through the platform's PDF renderer (no bitmap rendering), and the print pipeline probes it before the job is created — so an Android PDF rasterizes at the page size the document itself declares. The multi-page "only the first page will be printed" warning above now fires on Android as well.
- **Command-language label jobs that overflow their page are refused instead of printed truncated.** A command-language head (ESC/POS, ZPL, TSPL, …) prints exactly one bitmap per job. When a label's content is taller than the page, the browser paginates it into extra sheets — but the old check only counted the sheets the layout wrote before rendering, so the overflow went out silently with everything past sheet one dropped. The renderer now reports the final sheet count of the rendered page, and a job that paginated past one sheet fails with the existing "this printer's command language prints only one page per job" message before a single byte reaches the head. PDF printers are unaffected.
- **URLs fetched for printing can no longer be DNS-rebound.** A `data_url` fetch pins every hop to the address that passed validation, so a name that re-resolves before the connect cannot steer the request to a loopback, link-local or private address — the same treatment print callbacks already got.
- **Pairing-code guessing is throttled per source address.** Ten or more failed pairing attempts from one address inside a minute get a 429. The budget is separate from a paired phone's token checks, so a code-guessing host cannot block a real device (and vice versa).
- **Pairing can no longer take over another device's identity.** A pairing claim that reuses an existing device id must now prove it holds that pairing's current token (checked hashed, never stored); without the proof the claim is refused before the pairing code or a guest invite is spent, and the existing pairing keeps working. A device that has never paired gets its id issued by the PC and handed back in the pairing response, so two phones can no longer end up claiming the same id. Re-pairing a phone that predates this change to an upgraded PC asks to update the phone (or remove the old pairing on the PC); pairing to a PC that predates the change still works as before.
- **The same idempotency key no longer collides across devices.** Retry keys are scoped per caller: two different phones (or a phone and the desktop UI) can each reuse the same key without one silently receiving the other's job.
- **Phone-side print-via-PC history rows are recorded again.** The per-caller scoping above had invalidated the upsert the phone used to write its history row, so every via-PC attempt failed to land in the phone's history. The write is back (update-then-insert on the same key), so the phone's history shows the attempt, its outcome and the PC's name as before.
- **Printer passwords no longer travel to the app interface.** The printer list and edit sheet used to receive the stored IPP password and show it in the form; now the backend only reports that a password exists. The password field in the edit form always opens blank: leaving it blank keeps the saved password, typing one replaces it, and clearing a field you edited removes it — with a hint under the field while it is untouched. Test Print still uses the saved password on the backend side, so nothing else changes when you print.

### Changed

- **"Printed" is now "Sent to the printer" where the app cannot see the paper.** A job over a raw wire — USB, or Bluetooth printing directly with no driver — cannot be confirmed by the printer, so the history row, toasts and the Android result notification now say "sent to the printer" on success instead of "printed". The driverless mode is named "Direct printing (no driver)". Failures are worded as before, and IPP/system/driver jobs still say "printed".
- **Test Print checks the wire instead of printing a page you have to decode.** For command-language printers (ESC/POS, TSPL, ZPL, CPCL) the test is one plain line of text in the printer's own language — if you can read it, the wire works. Raster/PDF test pages get a visible border around the page so a blank sheet is obvious, plus a hint toast when nothing comes out. A driverless Bluetooth test no longer runs a second "is the printer there?" probe first: its socket is stateful, and a probe right before the real send can make the head drop the job.
- **One-tap Bluetooth add is confirmed, not blind.** Tapping a bonded Bluetooth printer now fills the Add sheet with a safe 2-inch (54 mm) paper width and ESC/POS, and opens the Advanced section so the width is something you can see and change before saving — instead of silently saving an 80 mm row. A hint explains the 2-inch vs 3-inch choice.

- **Japanese UI typography.** When the interface is in Japanese, the type is tuned for CJK: IBM Plex Sans now pairs with the platform's own Japanese face (Yu Gothic UI / Meiryo on Windows, Noto Sans CJK JP on Android) instead of the generic fallback, body line height rises to 1.7, and the Latin display treatments that read badly in Japanese are switched off — forced `uppercase` and letter-spacing on tracked headings are neutralised for `lang="ja"` only. Translated labels wrap (capped at two lines) instead of truncating mid-word; user-entered data (names, handles, addresses) still truncates as before.
- **Settings page split into section components.** The 1,789-line `Settings.tsx` is now a thin shell composing one component per section in `src/pages/settings/` (General, Background, Share, Data, Retention, Diagnostics + the Windows print-repair card). Each section owns its state, initializes from the local settings cache (no loading gate, no first-paint flicker) and reconciles with the backend on mount. Rendered markup, testids and deep-link behavior are unchanged.
- **Print, Designer and PrinterSetup pages split the same way.** The three remaining 1,700–2,100-line pages are now thin shells (108–287 lines) composing section components and small state hooks in `src/pages/print/`, `src/pages/designer/` and `src/pages/printer-setup/`. Rendered markup, testids and behavior are unchanged.
- Windows USB test/send no longer blocks a tokio worker thread (moved to the blocking pool like the spooler path).
- `IppPrinter::test` is now a connectivity check only; it no longer prints a real test page.
- **Phone styling moved from `src/mobile.css` into the components it styles.** The per-component phone rules (button/label weights and press states, card and field radii, input and select sizes, page header, bottom tab bar, sheet and dialog geometry, print action bar) are now `max-md:` Tailwind variants on Button, Card, Input, Label, Textarea, Select, Switch, Tabs, Sheet, Dialog, Layout, PageHeader, DataTable, History and the print flow, matching the repo's existing convention. `src/mobile.css` keeps only what is genuinely shared: phone tokens, cross-cutting touch/focus rules, and descendant rules an outer container must express. Rendered output is unchanged (verified against the e2e screenshot baselines and the 44px tap-target spec).
- **On Android, nothing dials the local network until you allow it.** The app no longer fires background mDNS scans or polls your paired PC while Android's local network permission is off — the calls that used to trigger Android's "connect to local devices?" dialog at random moments are gone. The quiet scan now runs when the Add Printer sheet opens (and again if you grant the permission later in system settings), and PC-pairing checks resume the same way.

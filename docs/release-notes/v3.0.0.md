# PrintNinja 3.0.0

**Release date:** 2026-11-02

**Previous release:** v2.4.0

**Downloads:** [Windows (MSI) · Linux (.deb / AppImage) · Android (APK)](https://github.com/SAR-dev/PrintNinja/releases/tag/v3.0.0) — Windows and Linux builds are currently unsigned (see [docs/SIGNING.md](../SIGNING.md)).

## Highlights

- **Find printers on your LAN.** The Printers page can now scan the network with mDNS and discover IPP and raw TCP (JetDirect, 9100) printers. Add a discovered printer in one tap.
- **Starter packs for new templates.** Every new template starts from a worked example — Receipt, Delivery Slip, Invoice, Shipping Label, Kitchen Ticket or Blank — chosen in the new two-step New Template dialog (pick a pack, then name your copy).
- **Print callbacks.** The REST API's `callback_url` now works: after a job finishes, the app POSTs `print.succeeded` or `print.failed` to your endpoint. HTTPS-only, retried on failure, optionally HMAC-signed.
- **Smarter printer/template matching.** Printers can carry a registered paper width, and PrintNinja warns when your template or chosen paper is wider than that paper — and remembers each printer's template + paper choice for next time.

## New features

### LAN printer discovery (mDNS)

- **Printers → Scan network** finds IPP and raw TCP 9100 printers on the LAN via mDNS; each result can be added in one tap (a new `discover_network_printers_mdns` agent command backs this).
- Phone pairing benefits too: `discover_peers_mdns` lets a phone find nearby PCs the same way.
- New `discovery/` module in the Rust backend with unit and integration tests; the bundled fake printer can advertise itself over mDNS for CI.

### Template starter packs

- The Designer's New Template flow is now a two-step dialog: choose a starter pack, then name your copy. The pack's HTML becomes your starting point.
- Packs: **Receipt, Delivery Slip, Invoice, Shipping Label, Kitchen Ticket, Blank**.
- Each pack is a worked example built from the template language itself (placeholders, `{{barcode}}`/`{{qrcode}}`, Tailwind), so there is always something concrete to edit down.

### Print callbacks (REST API)

Add `"callback_url": "https://…"` to a `POST /v1/print` request and the app POSTs the outcome to it once the job reaches a terminal state:

- Events: `print.succeeded` / `print.failed`, with job id, printer, template, error and duration in the body.
- **HTTPS only.** Private hosts unless you opt in; invalid URLs are refused up front with 400 and code `callback_url_invalid` (SSRF hardening).
- Retried a few times on failure. Duplicate requests (same `Idempotency-Key`) do **not** fire a second callback.
- With a shared secret set, the body is signed with an `X-PrintNinja-Signature` HMAC. See [`docs/ENV.md`](../ENV.md) for the `PRINTNINJA_CALLBACK_*` switches.

### Smart printer/template matching

- Printers can register a paper width (`paper_width_mm`), e.g. 80 mm for a roll thermal.
- PrintNinja now warns before a mismatched job: *"Template is 210 × 297 mm; this printer uses 80 mm paper"* — for both the template's page size and an explicitly chosen paper.
- Each printer's template + paper choice is remembered in a `print_prefs` setting: it survives reloads and printer switches.

## Behavior changes

- **`callback_url` is now honored.** In 2.x the API accepted the field and rejected the request with 400 ("not supported"). Requests with a valid HTTPS `callback_url` are now accepted and the callback fires; invalid URLs are rejected with a clearer `callback_url_invalid` error.
- **New Template dialog is two steps** (pick a starter pack, then name). There is no more single-step "new blank template" flow; choose **Blank** for what that used to be.
- System printer rows now carry a `paper_width_mm` field (used for the mismatch warning above).

Nothing else is breaking: settings, templates, paired phones and API clients from 2.x continue to work unchanged.

## Bug fixes

- Discovered IPP printers now show their address in the correct format.
- Windows: notification allow-list path handling fixed (backslash separators).
- Fake agent seed data is now UTF-8-safe (bare `atob` mangled non-ASCII characters).
- Removed a fully-duplicate `DiscoveredPrinter` type from the shared agent types.
- Wording fixes in Devices and Printer setup screens (English and Japanese).
- Virtual-printer test fixture no longer races its own job flush.

## Documentation

The docs were restructured for this release:

- `docs/ARCHITECTURE.md` is now a ~1,200-word overview (system map, pipeline, phone↔PC sequence, "where does my print fail"); the details moved to deep dives in `docs/architecture/`: rendering and layout, printers and transports, queue and history, phone and PC sharing.
- New: `docs/GLOSSARY.md` (plain meaning of every term the app uses), `docs/DECISIONS.md` (the "why" behind the sharing rules), `docs/DEVELOPMENT.md` (quick start, layout, commands, release).
- The README now targets end users, with screenshots for the first-print path; the developer section points at `DEVELOPMENT.md`.
- 15 stale in-code doc references repointed; `TODO.md` deleted (all items implemented).

## For developers

- New agent commands: `discover_network_printers_mdns`, `discover_peers_mdns`.
- New API surface: `callback_url` support with `callback_url_invalid` validation code; OpenAPI document updated.
- New e2e specs: `templatePacks`, `printMatching` (per-printer preference round-trip), LAN scan add-flow in `printers`.
- The README version badge is now kept in sync by the release scripts instead of by hand.
- Verified before release: cargo tests, e2e (Playwright/Chromium), vitest (943 passing) and `tsc -b` all green.

## Upgrade

Download the installer for your platform from the [releases page](https://github.com/SAR-dev/PrintNinja/releases/tag/v3.0.0) and run it over your existing install. Your printers, templates, pairs and history are kept.
